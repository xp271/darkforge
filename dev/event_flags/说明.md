# 事件标记编号：哪些能用、怎么挑

整理于 2026-10-24（一键出售被死亡事件误触发之后）。挑新标记前先跑 `python scan_flags.py 起 止`。

## 规则

- **按千分块**：标记 N 在第 N ÷ 1000 块，每块 1000 位。存档里只存块表（BST）里列了的块。
  - 块表里有不代表一定存档：1040490 块在表里，运行时却是游戏另外分配的，重启就清空，还会被别的数据写坏（见下面「现在用的标记」）。
- **事件编号也是标记**：「事件编号 + 槽位 = 事件结束标记，事件完全结束时点亮」（Souls Modding Wiki）。
  - 挑标记要避开所有事件编号，包括「编号 + 槽位」。
  - 实测：RNG Lands 公共事件里的 9970 / 9972 / 9977 会点亮同号标记。9977 是「玩家死亡」时跑的，以前每死一次就触发一次一键出售。
- **会重置的段**：Elden Ring 的 8 位地图标记，后四位 ≥ 2000 的在事件系统重置时清零（死亡、读档、传送），其他游戏是 ≥ 5000。
- **自己加地图标记**：Wiki 建议从同一张地图原版 8 位事件编号所在的那一万段里取（例如原版有 10003010，就用 10000000~10009999 里的空号）。

## 官方定义表（游戏自带的 EventFlag 定义，0~99999 全局段）

来源：[Elden Ring Event Flag Reference](https://soulsmods.github.io/elden-ring-eventparam/)（EFID_common）。

| 编号 | 官方写的用途 | 能不能用 |
|---|---|---|
| 0~8999 | 系统、角色状态、各类事件 | 原版在用 |
| 9000~9949 | 事件标记（篝火、Boss 击杀 9100~、奖杯 9300~、结局 9400~、道具 9500~、天气等） | 原版在用 |
| 9900~9923 | 测试用事件编号（篝火、NPC 对话测试） | 别用 |
| **9950~9979** | **表里没有定义** | 第 9 块会存档（难度实测能存）。但 RNG Lands 在这里放了事件 9950、9970~9973、9977 |
| **9983~9989** | **デバッグフラグ_用途無し（调试位，无用途）** | 9983~9988 能用；9989 被原版公共事件 1040 判断 |
| 9990~9999 | デバッグフラグ00~09（调试位） | 9990~9993 被原版事件判断；9994~9999 没有脚本引用 |
| 60480 / 60490 / 60530~60590 | 成长解禁预留（记忆栏 8~9、护符栏 3~9） | 别用，引擎可能会读 |
| 62000~63999 | 地图道具、地图点 | 原版在用 |
| **92000~92599、93000~93999** | **予備（预留：地图道具获得 / 地图点开放 / 获得演出）** | **最干净的大段**，见下 |

**92000~93999（2026-10-24 扫过）**
- 在存档块表里（第 92、93 块）。
- 原版、RNG Lands、随机器、重随包、BossRes 的事件脚本、对话脚本、参数标记字段都没引用。
- 事件编号（含编号 + 槽位）也没有落在这里的。
- 我们自己的标记都已经挪进 93000 块，分配见下表。93670~93673 给了斗技场试炼（2026-11-10），93000 块里已经没有挑剩的连号空位，新加的要先扫描再查下表；93981 以后要先查（93910 难度锁、93911~93980 魇化次数只写在代码和 DLL 定义里，扫描工具看不到）（93677 给了 Boss 取回力量的提示，93686 给了叙事开场提示），93645~93656 给了事件脚本放音效：这两段是商店版装备继承用过的，2026-10-31 改成装备工坊后不用了，测试存档里可能还亮着；93614 / 93615 给了唤声船的碎片 / 战灰标记，rr/mariner.py，扫描工具看不到只在 DLL 定义里用的标记）；92000 块用了 92000~92581。

我们加的**事件编号**（WISH_EVENT 1040490700、DIFF_EVENT 710、DIFF_INIT_EVENT 712、MANUAL_EVENT 740（说明书补发，sc\start.py；以前 735 起）、START_EVENT 750、COOKBOOK_EVENT 760（槽位用到 863）、NOTE_EVENT 870 / CLEAR_EVENT 871（原版闪烁提示，sc\notes.py）、SOUND_EVENT 880（事件脚本放音效，sc\sounds.py）、VARRE_EVENT 876（白面具支线刺手指那一段的兜底，877 当它的临时标记「卡过」，sc\varrefix.py；720 起那一段会被乱写，没用）、CONTAINER_EVENT 950、DELIVER_EVENT 960、DEATHBACK_EVENT 878（遗失的未鉴定物品放回背包，sc\identify.py；961~999 是 bossaward 961 的槽位，别用），以及训练场的 STATION_EVENT 11102990）**故意留在不存档的 1040490 块**：
- 事件跑完会点亮同号标记。放在会存档的块里，事件跑完一次就会被存档记住，以后读档不再跑。
- 这些事件里有要每次读档都跑的，比如难度初始化、补发说明书。
- 它们和任何标记都不撞。

以前踩过的坑：
- 1040490781~792：被写坏，没点出售也会卖。
- 9970~9981：和 RNG Lands 的事件编号撞了，死亡时会卖防具。
- 9983~9988、9994~9999：没有冲突，但 9994~9999 是官方调试位，所以统一挪进了 93000 块。

## 挑新标记的检查清单

1. 官方表里是「予備 / 未使用 / 用途無し」，或者没有定义。
2. `scan_flags.py` 扫过：不是事件编号（含编号 + 槽位），事件、对话、参数里都没人引用。
3. 要存档的话，块要在存档块表里，而且实测重启游戏后还在；只当临时请求用的话可以不存。
4. 给 DLL 用的「请求」类标记再加一道上下文判断（比如只在赐福菜单开着时才处理），别人误点亮了也不会出事。
